# Question-writing rules

These initial rules are authoring standards, not rules inferred from real user removals. Add evidence-backed rules below as feedback is resolved.

- **R1 — One defensible answer.** Exactly one choice correctly answers the question under the explicit assumptions. Check every alternative, including boundary cases. When asking for a definition or equivalent condition, test equivalence, not merely implication: a stronger or weaker condition may hold on some of the same examples without being an equivalent definition. Do not label a loose upper bound wrong when the question asks only for an upper bound; ask for a tight bound when appropriate.
- **R2 — State the model.** Specify directed/undirected, simple/multigraph, connectedness, weight restrictions, encoding, worst-case/expected/amortized, and operation costs when they affect the answer.
- **R3 — Teach the misconception.** Every distractor has a specific short explanation of its error. Correct-answer explanations state the key invariant or reason, rather than repeating the answer.
- **R4 — Difficulty is conceptual.** Harder distractors should expose a plausible misconception, omitted hypothesis, or reversed implication. Avoid grammatical traps, vague qualifiers, gotchas, and implausible filler. A three-tier label is editorial judgment; tune it from experience.
- **R5 — Don’t reveal the answer by style.** Prefer parallel length, grammar, and notation. Avoid “all of the above”, “none of the above”, and answer-position references; alternatives are independently shuffled and sampled.
- **R6 — Ground and verify.** Cite a textbook, original paper, or official course/reference supporting the claim. Read the relevant passage, then check the argument independently. A URL and a passing schema validator are not proof of mathematical correctness.
- **R7 — Preserve continuity.** IDs are stable. Correctness, assumptions, answer wording, explanation substance, or distractor changes require incrementing the question revision. Fixing a purely cosmetic typo may keep it. Retire problematic questions with `status: "retired"` and preserve their history.
- **R8 — Keep each question focused.** Test one idea in a short mobile-friendly prompt. Use `$...$` and `$$...$$` for TeX; JSON requires doubled backslashes. Prefer application, comparison, and counterexample questions alongside definitions.

## Direct authoring feedback

- **R11 — Introduce symbols and bind variables.** The learner's direct requests on 2026-11-19 require logically sound, self-contained questions with explicit variable domains. Introduce the universe before a relation: “Let $A$ be a set and $R\subseteq A\times A$ a binary relation on $A$.” Write “$(x,x)\in R$ for every $x\in A$” or “$\forall x\in A\; (x,x)\in R$”, not an unbound $(x,x)\in R$. Define predicate notation such as $R(x,y)$ if used. Introduce graph symbols, parameter types, index ranges, and auxiliary notation before use in the prompt or the same choice/explanation. Each choice inherits the prompt, never another choice or an earlier card. Check quantifier scope and order, whether variables may coincide, and empty-domain cases; state nonemptiness when a maximum or other expression needs it. Incorrect alternatives must still be well-formed mathematical statements. This rule comes from conversation feedback, not an app report ID.
